# 全国一覧への意見掲示板

## 仕様
- 公開ページ: `/japan/feedback`。全国一覧から移動し、連載申請フォームとは別にする。
- 投稿はログイン不要で即時公開。名前は任意、未入力は「匿名」。本文は2000文字以内。
- 公開一覧は20件ごとに新しい順で表示。日時が同じ場合はIDで順序を固定。
- 管理ページ: adminの`/local-edition-feedback`。管理者だけが非表示・再公開できる。管理側もページ切り替えで過去の投稿を確認できる。
- 本文はHTMLやMarkdownとして実行せず、そのまま文字として表示する。
- 投稿制限はIP由来のハッシュごとに毎分3件、掲示板全体で毎分30件。掲示板専用のテーブル・RPCで同時投稿も原子的に集計し、1時間前より古い制限データを削除する。IPアドレス自体は保存しない。

## DB変更と認可
新規テーブルは`public.local_edition_feedback`（投稿）と`public.local_edition_feedback_rate_limits`（投稿制限）の2件。
`id`、`display_name`、`body`、`is_hidden`、`created_at`を保存する。
連載申請のテーブル・既存レコードは変更しない。
RLSを有効化し、anon/authenticatedの直接アクセスは拒否。
保存・取得はcreateAdminClient経由。非表示操作はServer Action内でrequireAdminを必須にする。
公開側は非表示行・管理用フラグを返さない。
新規RPC `consume_local_edition_feedback_rate_limit` はservice_roleのみ実行可能。
本番の読み取り調査で既存API用の投稿制限テーブル・RPCが未導入と確認したため、これらに依存しない構成とする。

マイグレーション:
`supabase/migrations/20261115132932_create_local_edition_feedback.sql`

## 確認
- 共有入力検証6テスト成功。
- 実ローカルSupabaseの統合11テスト成功（即時公開・非表示/再公開・直接アクセス拒否・制約・ページ切替・連投制限、RPCの同時実行・時間枠切替・キー分離・古いデータ削除・権限）。
- 型はローカルDBから生成して新規2テーブル・関数分を同期。
- 全体型チェック・全体ビルド成功。変更ファイルのBiome成功。
- 全体単体テストは既存のWindowsパス区切り依存routesテストで失敗。Linux CIで確認。
- Windowsの既定DBポートが予約されているため、検証用コピーでAPI65421/DB65432を利用。追跡中のconfig.tomlは変更しない。
- ブラウザでフォーム送信後、すぐに公開一覧へ表示されることを確認。

## 本番反映
本番DBへの適用は未実施。ユーザー承認後に、新規2テーブルと関数1つを作るこのマイグレーションだけをレビューして適用する。
`supabase db push --include-all`などで他の未適用マイグレーションを一括適用しない。
通常のサイトデプロイworkflowからDB変更は行わない。
テーブルが未準備の場合はページに準備中と表示し、投稿ボタンは無効にする。
環境変数・秘密情報・認証設定の変更は不要。
